# 工作台交互与性能改进

2026-10-06，起点 `561a6dc`，开始时工作树干净。本轮沿用 ask-matt 的实现、回归和独立审查流程，基于真实桌面 fixture 与可重复性能测量改进现有功能。无模型调用，不修改用户数据库或运行时配置，不推送、发布。

## 基线验收

macOS 原生工作台已完成无 Provider 创建工作区与协作、两次 OMP fixture 派发、保存输出、证据复用、离线重载及 hash 保持不变。第二次实际 CLI `--spec` 与交接预览逐字相同；离线无 worker-start。最后基线运行约 44.2 秒。Focus 兼容 smoke 通过；三进程重启恢复通过，退出码 `[0,1,0]` 中的 1 是预期故障注入，回放未重复请求。

修正了测试中复用已卸载预览元素句柄的问题。截图使用真实 DOM 滚动并等待两帧绘制，不能用“wheel action 被接受”推断嵌套面板已滚动。可见性保护保持原样，窗口被其它应用切走时用真实窗口聚焦恢复，不伪造前台状态。

## 已复现的问题与实施范围

1. 初次列表或环境检测的迟到响应会覆盖刚创建的工作区、协作或手动检测结果。通过公开 UI 的延迟响应回归锁定，合并本地已确认项，并使较新的检测拥有结果。
2. 工作台切到路线图再返回，会丢失未发送任务和所选协作。改为由应用实例保留按协作区分的编辑草稿与选择；预览确认不缓存，返回后仍需重新预览。关闭应用后的持久恢复不在本轮承诺中。
3. 历史列表会全量传输正文，折叠详情仍把全部正文挂入 DOM。改为固定 50 条摘要页、按展开读取详情、限制当前页 DOM；已选证据跨页保留并明确显示，上限 32。
4. 来源图缺少方向箭头，默认按钮样式挤压缩放控件。保留既有 ReactFlow，修正控件样式与方向表达，明确图仅包含已加载摘要。未选择图谱路径时不展示大块历史树。

新增分页和详情接口只读已有不可变记录，不增加数据库迁移，不修改原文、Receipt 或 hash。游标绑定具体工作区/协作与记录类别，详情读取验证归属；显示和性能调整不改变派发、审批或未知结果语义。

## 性能基线与边界

真实 schema 1–10 的内存 SQLite，1,000 条 evidence（每条正文 64 KB）和 1,000 条 handoff（每条正文 32 KB），现有全量 JSON 约 96.54 MB，SQL 与 Python 解码中位约 107.76 ms。候选 50 条摘要投影约 23.45 KB / 1.80 ms。候选测量用于确定方案，不替代最终实现测量；已有工作区/协作索引可用，无需新增索引。

实际 AgentHandoffPanel 的隔离 jsdom 测量，500 + 500 条折叠历史仍挂载 1,000 个 pre、4,800 万正文字符、7,526 个 DOM 元素；初挂约 125.25 ms，标题输入到 React 提交中位 117.21 ms。空历史分别约 2.50 / 0.82 ms。图与 ContextTree 被隔离，测试查找控件的时间不计入输入测量；不能声称这是桌面完整操作延迟。

既有固定 25 ms CLI 延迟基准：2 次预热、9 次计量，中位 83.319667 ms，每快照仍为 5 次调用，共 45 次。未观察到该路径的新增工作量；不把运行间波动当作性能改进。每五秒轮询本来就不重读证据或交接历史。
