# Agent 刷新与工作区内容读取

2026-09-26。范围及验收条件见 [本轮计划](REFRESH_STORAGE_PLAN.md)。DesktopBridge 与 RepositoryPort 保持不变，没有新增依赖。

## 架构结果

AgentMissionView 集中管理刷新：一个正在执行的读请求，加一个可合并的后续请求。定时 tick 不积压；显式刷新和操作完成后的刷新不会被丢弃。页面隐藏后不发起自动读取，恢复可见时重新确认状态。revision 仍决定结果归属，后台已派发的任务继续运行。

启动、回复、释放及重连都遵守恢复可见后的确认要求。当前读取失败后仍允许用户显式重连，后端继续核验运行时身份与未确认 Operation。旧快照只供查看，不构成操作授权。

Repository 的内容查询从工作区内的四类引用出发，再按 content_block 主键取值。八次逻辑读取、快照事务、去重以及 `created_at, id` 排序均保留。共享内容仍可由多个工作区引用，不会遗漏只存在于 Checkpoint 或 Draft 的内容。

新增 schema 7 迁移只创建 `(workspace_id, content_block_id)` 索引。Manifest Item 的既有复合外键保证所属工作区，历史内容与 Receipt 不改写。新增索引占用磁盘，写入 Manifest Item 时也需维护；首次升级建索引的耗时取决于既有数据量，本轮未将其作为性能收益。

## 可复现 SQL 基准

运行 `python3 scripts/benchmark-context-content.py`，要求 Python 3.9+、SQLite 3.37+。脚本使用真实迁移，从 Rust 源码提取当前查询，与优化前的查询在同一个内存库中比较，校验完整有序结果相等。

本机 SQLite 3.54.0。目标工作区固定 20 个内容块，每个有 Turn 和 Manifest 引用。无关工作区逐步增加同样的历史。每次查询预热 2 次、测量 7 次，取中位数。VM 步数另行测量，以 100 步为粒度，不将计数开销混入计时。

| 无关工作区 Turn / Manifest 数 | 原查询中位数 | 新查询中位数 | 原查询 VM 步数 | 新查询 VM 步数 |
| ---: | ---: | ---: | ---: | ---: |
| 0 | 0.0310 ms | 0.0222 ms | 1,900 | 1,400 |
| 1,000 | 2.3156 ms | 0.0242 ms | 182,900 | 1,400 |
| 10,000 | 24.3943 ms | 0.0234 ms | 1,811,900 | 1,300 |
| 30,000 | 75.5502 ms | 0.0239 ms | 5,431,900 | 1,300 |

执行计划由 `SCAN b` 加四个相关子查询，变成四类工作区索引读取、引用去重与内容主键查找。两种查询都使用最终 schema，原查询仍选择原有内容索引。这里只测单条内容读取 SQL，不包括磁盘 I/O、其余七次读取、Context 编译、IPC 或渲染，不能据此声称整个应用获得相同倍数提速。大工作区自身的读取代价仍随自身数据增长。

原始输出与执行计划见 [测量记录](measurements/context-content-20260926.jsonl)。

## Agent 调用次数

公开组件测试中，先完成首次读取，再将页面隐藏 60 秒。此前每 5 秒执行一轮快照和回执读取，即 12 轮、24 次 IPC；现在该区间新增调用为 0，返回可见时立即补一轮。若隐藏时已有请求在执行，它仍可完成，但过期结果不会提交。本轮没有测量 CPU、能耗或真实 Orca 网络延迟。

## 回归与审查

- 前端最终 134 项测试通过，AgentWorkspace 占 19 项；新增行为包含尾随刷新、mutation 期间不轮询、隐藏恢复、迟到结果、StrictMode 和重连保护。
- Rust 269 项库测试与 3 项原生 IPC 测试通过；已有 CLI 延迟基准保持显式 ignored，本轮未重复运行。
- 38 项 SQLite 测试包含冻结旧库 v1–v4 的真实升级、历史迁移 checksum、外键、不可变内容与 Receipt 检查。新增回归测量 SQLite VM 工作量，不用易受机器负载影响的毫秒门槛。
- 工作量回归在旧查询上先失败：同样 20 个目标块，加入 1,000 条无关历史后从约 1,800 增至 173,800 步；修复后通过。
- HTTP/Orca fixture 10 项、Node 工具链 3 项、TypeScript/Vite、WebView 类型检查及 Rust fmt/clippy 通过。
- Standards 独立审查无阻断问题。Spec 审查发现重连遗漏刷新保护，已修复并通过两条参数化回归，复审无遗留问题。
- macOS 原生 Context Tree smoke、双 Agent fixture（40.7 秒）和三进程崩溃恢复均通过。恢复流程退出码为 `[0, 1, 0]`，中间的 1 属于预期故障注入；恢复后验证成功，整体命令退出 0。原生工具仍有现存窗口探测与清理警告，未将这些警告记为产品功能失败或忽略失败断言。
- Windows/Linux 未实际运行；本轮没有调用付费模型或宣称最新 OMP 的真实 Agent 已验证。

Branch 历史联接放大、回执延迟渲染及全文搜索留待单独测量与实现，详见计划中的暂缓项。
