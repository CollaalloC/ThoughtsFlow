# 以现有 Agent harness 为执行基础的上下文工作台

2026-10-06 用户明确要求：ThoughtsFlow 主要承担对话上下文的图形化管理，以及 Agent 工作台与工作流编排；模型、认证和 Agent 工作能力继承现有 Agent，不再要求用户重新配置 Provider。此决定调整 ADR 0001 的产品主次，保留其中的运行时所有权、任务身份与未知结果规则。

## 决定

- **主流程**是工作区 → 选择上下文与证据 → 预览交接 → Agent 执行 → 保存观察 → 复用证据。新建工作区和派发任务不依赖 Provider Profile。原模型直连作为兼容入口保留。
- **ThoughtsFlow**拥有用户选择、图上关联、交接快照、输出观察、审阅与本地操作记录；**Orca**拥有 Run/Task/Dispatch、隔离工作区和执行器生命周期；**Agent harness**拥有模型认证、工具循环、Skills、MCP、内部上下文与审批策略。
- **Context Handoff** 是冻结的出站任务文本及来源，其 hash 证明工作台交给 harness 的内容。它不证明 harness 内部额外系统提示、工具结果、压缩或最终供应商请求。历史 Context Receipt 的原始语义和 hash 不变。
- **Agent Evidence** 是用户显式保存的一次有界输出观察。它记录 task/dispatch、读取游标、文本 hash、观察时间及当时状态；分页结束或执行器退出均不代表任务成功。新任务可以显式引用已有证据，形成可追溯的人工工作流。
- 模型未知时显示“沿用 Agent 配置”。不把普通 Provider 值填入 Agent 输出，不提供上游未支持的模型覆盖。当前 OMP worker 由 Orca 启动，保留原生工具审批入口。

## 存储与恢复

新交接与证据使用独立、追加式记录，不伪造为 Provider Model Run，不修改历史请求或原始回执。旧数据库通过新增迁移增加表；不更改旧迁移的内容或校验和。

交接预览无需 Provider。提交时重新编译并校验 hash，核验工作区归属、cursor/draft/branch 版本、相关系统提示与检查点/继承集合，在同一 SQLite 事务中落下 pending 操作与交接，然后才调用 Orca。修改任何输入都要求重新预览。全新任务必须提供预览确认；旧输入只可精确重放已有操作，返回原记录，不能重新计算或再次派发。不明确的外部结果保留 unknown。

结果捕获的客户端 ID 是幂等标识。同一 ID 和同一输入读取已存结果，不再次访问运行时；不同输入复用 ID 会拒绝。保存的输出可离线读取。证据来源为本机运行时返回的文本，不接受界面任意文本作为“Agent 输出”。

## 取舍与后续

首先复用已验证的 Orca supervised worker 路径，完成图谱与执行之间的交接、证据闭环，不建设第二套 Agent 调度器。图上的依赖表达来源关系，当前由用户决定是否派发，不声称自动 DAG 调度。

完整原生聊天应通过有会话所有权的 Agent 会话接口实现：OMP Direct RPC 可以复用既有配置；Orca structured session 当前限定 Claude/Codex，不能假定 OMP 也支持。后续适配必须覆盖模型目录、会话分叉、审批、取消、完成条件与断线恢复，且绝不让 Orca 和 ThoughtsFlow 同时控制同一会话。当前代码任务依赖已登记仓库，不宣传为已实现任意目录的通用聊天。
