## 已实施的兼容修复

Orca 新增 `ORCA_AGENT_SESSION_ID` 作为 structured-session caller。ThoughtsFlow 从这样的会话环境启动时，继承的 caller 会与显式 `--from` 协调者身份冲突。现有子进程环境过滤遗漏了此变量，现已加入统一过滤列表；保留其它无关配置。

回归先在旧代码中复现继承外部会话 ID，再验证真实子进程接收的环境已清除该值。测试使用独立测试进程注入环境，避免并发测试全局污染。Windows 不区分大小写的变量规则也有单测。5 项 `agents::orca::tests` 通过；实际子进程运行证据仅来自 macOS。

固定来源：[caller 环境](https://github.com/stablyai/orca/blob/v1.4.220/src/shared/agent-session-caller-env.ts)、[caller 参数与 fencing](https://github.com/stablyai/orca/blob/v1.4.220/src/cli/session-caller-flags.ts)。原 `orchestration.contract.v1`、contractVersion 1、worker 输出/观察接口保持兼容；内部 schema 42→43 属于 Orca，不迁移 ThoughtsFlow 数据或历史 Receipt。

## 值得吸收的新能力及边界

OMP 18.4.12 新增 `auth-gateway stdio`：可沿用已有认证、models.yml、扩展 provider 与角色选择，不要求新增 HTTP listener 或 bearer token；若 OMP 已配置 broker，继续遵循其配置。但是它仅提供模型推理，不包含工具循环、会话与分叉。其响应先完整收集再返回，即使请求 `stream:true` 也不是逐 token 流。当前 ThoughtsFlow 的 HTTP Gateway 模型目录/chat/SSE 契约仍兼容，HTTP serve 仍需 broker。

来源：[认证和模型配置复用](https://github.com/can1357/oh-my-pi/blob/v18.6.1/packages/coding-agent/src/cli/auth-gateway-stdio.ts)、[stdio 响应缓冲](https://github.com/can1357/oh-my-pi/blob/v18.6.1/packages/ai/src/auth-gateway/stdio.ts)、[HTTP serve 条件](https://github.com/can1357/oh-my-pi/blob/v18.6.1/packages/coding-agent/src/cli/auth-gateway-cli.ts)。

用户将产品定位调整为现有 Agent 的上下文图形工作台与工作流编排平台。真正继承 harness 需要原生 Agent 执行或会话接口，不能用上述网关冒充：

- **OMP Direct RPC** 共用原生配置和认证。`get_available_models` 发现模型；`set_model` 改会话模型，不写全局默认值。`prompt` ACK 只表示接纳，需按同一 ID 验证 `prompt_result`；仍有异步工作时还需 `session_settled` / `get_state.isSettled`。`fork` 创建并切换会话；恢复必须尊重 session 所有权，不能自动重发未知 prompt。18.5.1 的新能力是 wire schema/generated clients，V2 协商本身在此前版本已经存在。[RPC 文档](https://github.com/can1357/oh-my-pi/blob/v18.6.1/docs/rpc.md)、[RPC 实现](https://github.com/can1357/oh-my-pi/blob/v18.6.1/packages/coding-agent/src/modes/rpc/rpc-mode.ts)、[模型设置](https://github.com/can1357/oh-my-pi/blob/v18.6.1/packages/coding-agent/src/session/model-controls.ts)。
- **Orca structured agentSession** 有会话、模型目录、事件、审批和提问接口，但 create schema 当前只允许 Claude/Codex，不包括 OMP。公开 CLI 没有通用 chat/session 命令；不猜测接口。[严格 schema](https://github.com/stablyai/orca/blob/v1.4.220/src/shared/rpc-contract/structured-agent-session-params.ts)、[会话 RPC](https://github.com/stablyai/orca/blob/v1.4.220/src/main/runtime/rpc/methods/structured-agent-session.ts)。
- **Orca OMP worker** 继续继承 OMP 自身模型、工具、Skills、审批配置，不支持 worker `--model` / `--effort` 覆盖。原生聊天模型目录属于另一条调用路径。[worker 参数](https://github.com/stablyai/orca/blob/v1.4.220/src/cli/specs/orchestration-worker-specs.ts)、[OMP 目录](https://github.com/stablyai/orca/blob/v1.4.220/src/shared/agent-session-option-catalog-omp.ts)。

本轮产品实施与后续会话接入的范围见 [Agent 工作台计划](../AGENT_WORKBENCH_PLAN.md)。
