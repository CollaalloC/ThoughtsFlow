## 已核实的上游契约

本机 `herdr-core --version` 为 `hc 0.1.17`，对应官方 tag `v0.1.17`、提交 `ce87721557176f6cddaac1c7aefbf76929923263`、Apache-2.0。官方 core 仓库 latest-release API 返回 404，因此只声明已核实此 tag，不猜测最新稳定版本。

- `schema`、`connect` 和部分平台的 `server status` 可按需启动 core，因此只用 `--version` 做被动检测，协议从固定源码 schema 核实。
- `connect` 提供逐行 JSON-RPC，Unix socket / Windows named pipe 由 core 管理；`hello` 返回 generation、稳定 core ID 和方法声明。
- `terminal.run(argv: [template, task])` 由 core 解析模板、等待就绪并投递首条消息。检查 `first_message.sent`，不能只凭 terminal 地址认为任务已经送达。
- `terminal.get/list` 返回终端生命周期和原生 OSC 7501 状态，两者不证明任务验收成功。
- `terminal.read(lines:0)` 是屏幕观察。历史读取可能滚动 TUI，因此工作台不自动读取历史或伪造分页游标。
- `terminal.send` 使用 `if: idle` 和 `force:false`；`terminal.rm` 只移除已结束终端，确认返回的 `removed` 是准确地址。
- 测试使用独立 HC_SESSION、临时 XDG 配置/状态与专用 socket，清理只涉及本轮创建的终端及测试 core。

固定来源：[协议说明](https://github.com/herdrdev/herdr-core/blob/ce87721557176f6cddaac1c7aefbf76929923263/schema/README.md)、[OpenRPC schema](https://github.com/herdrdev/herdr-core/blob/ce87721557176f6cddaac1c7aefbf76929923263/schema/hc.openrpc.json)、[模板](https://github.com/herdrdev/herdr-core/blob/ce87721557176f6cddaac1c7aefbf76929923263/docs/templates.md)、[首条消息实现](https://github.com/herdrdev/herdr-core/blob/ce87721557176f6cddaac1c7aefbf76929923263/crates/herdr-core/src/templates.rs)。

## 架构与数据

删除活动 Orca CLI/receipt 实现及旧 live 测试入口，新增独立 JSON-RPC adapter。任务输入通过 stdin 传输，不将任务正文拼进 shell；只有用户的原生模板拥有 Agent 启动命令。窗口层选择模板与工作目录，不再登记 Orca 项目或要求 OMP 专属模型字段。

schema 11 只增加不可变执行绑定表。旧数据库升级逐字节保留历史 Orca Mission、操作回执、交接和输出原文；记录缺少 runtimeBackend 时按 Orca 只读解释，不绑定到新 core。迁移失败回滚新 schema 和迁移历史。旧 Context Receipt 与既有迁移文件不修改。

未知派发、首条消息不明、错误 core/terminal 身份和绑定提交失败均不自动重派。保存输出时限定 Mission/Execution，并保留读取前后准确终端身份。终端完成只显示待核实；没有引入隐藏调度器或自动任务验收。
