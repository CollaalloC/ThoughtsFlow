## 已核实的契约与取舍

### OMP

比较 [v18.3.2…v18.3.5](https://github.com/can1357/oh-my-pi/compare/v18.3.2...v18.3.5) 固定源码 blob：`docs/rpc.md`、RPC mode/types/client、Auth Gateway CLI、`packages/ai/src/auth-gateway/` 以及 Gateway 模型目录与 OpenAI chat 测试保持不变。ThoughtsFlow 当前 Gateway 的模型目录、chat/SSE 与 Auth Broker 边界无需改动。

- [18.3.3](https://github.com/can1357/oh-my-pi/releases/tag/v18.3.3) 新增 live steering 与 `omp skill list [dir] [--json]`。技能 JSON 返回 `skills` 与 `warnings`，可用于后续明确需要的技能发现功能；本轮不添加没有使用入口的接口。
- [18.3.5](https://github.com/can1357/oh-my-pi/releases/tag/v18.3.5) 新增 OMP 会话管理的提示词缓存预热。`providers.cacheWarming` 支持 `off`、`streaming`、`idle`，默认 `idle`。预热会重放上次模型请求，在首个生成 token 时终止，可能增加后台模型请求；上游依据预计节省额与预热成本差超过 $0.05 决定是否执行，并在缓存未命中时停止。idle 仅用于五分钟缓存项，未声明 `Model.promptCache` 生命周期的模型不预热。
- 同版移除 stream 层 `anthropicCacheRefresh` 与 `anthropicCacheRefreshRequest`。ThoughtsFlow 未直接依赖这些 TypeScript SDK 接口，不需要模拟或恢复它们。预热策略归 OMP 会话管理，不注入 ThoughtsFlow 的 Model Run、Gateway 配置或历史 Context Receipt，也不能据此宣称 ThoughtsFlow 已提速。
- `agent_end.awaitingAsyncWork` 表示可能仍有后台工作，不代表整个任务成功；当前生命周期仍由 Orca 管理。继续保留明确执行关联、未知结果不自动重派和历史回执不可变的规则。

源码：[Gateway 服务](https://github.com/can1357/oh-my-pi/blob/v18.3.5/packages/ai/src/auth-gateway/server.ts)、[会话事件](https://github.com/can1357/oh-my-pi/blob/v18.3.5/packages/coding-agent/src/session/agent-session-events.ts)、[模型目录类型](https://github.com/can1357/oh-my-pi/blob/v18.3.5/packages/catalog/src/types.ts)、[技能目录 CLI](https://github.com/can1357/oh-my-pi/blob/v18.3.5/packages/coding-agent/src/cli/skill-list.ts)。
