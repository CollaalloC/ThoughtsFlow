## 可选的原生模型请求

当前固定源码已支持为 OMP supervised worker 传入 `--model`，仍不支持 `--effort`。ThoughtsFlow 沿用 OMP 作为完整 harness：模型解析、认证、工具、Skills、MCP 和审批归 OMP 所有。没有新增 Provider、认证或工具执行生态。

- 默认选择“沿用 OMP 配置”，不会增加模型参数或模型发现调用。
- 用户可选择“指定本次模型”，填写原生选择器，例如 `provider/model` 或 `@smol`。选择器作为不透明文本传给 OMP，不在工作台展开角色别名、猜测实际模型或改变全局配置。
- 预览和历史记录明确标为“请求模型”。切换选择或修改文本后必须重新预览；交接 hash 冻结文本、来源和可选选择器。
- 模型选择器要求 1–512 个 UTF-16 单元，不接受首尾空白或控制字符；模型 ID 内的 `/` 不作拆分。
- 默认 `None` 继续省略新增字段，旧输入序列化与交接 hash 保持一致。数据库 schema 仍为 10，无数据迁移。已有操作先按原输入恢复，不因运行时离线或新能力检查而重新派发。

派发时沿用当前 Mission 身份和在线连接检查，额外要求 `orchestration.worker-launch-preferences.v1`，随后只增加一组 `--model` 参数。这个能力名是必要条件，并非 OMP 支持证明：Orca 1.4.220 已对其他执行器声明它，但当时会在 worker 创建前拒绝 OMP 的模型参数。ThoughtsFlow 不依据能力名或版本号跳过回执核验，也不会在失败后删掉模型参数重试。

收到回执后，除准确 Run/Task/Dispatch 外，还必须同时验证 `launch.requested` 和 `launch.effective` 的 `agent: "omp"`、原始 `model` 选择器与显式 `effort: null`。字段缺失、模型不匹配或 effective 尚未落定时，保留原始回执并将结果记为 unknown，阻止自动重派。该回执只确认启动参数匹配，不能证明 OMP 最终解析或请求了哪个模型。

固定来源：[worker CLI 参数](https://github.com/stablyai/orca/blob/041baf356b368d773f333e76375ce860fba2481b/src/cli/specs/orchestration-worker-specs.ts)、[OMP 选项契约](https://github.com/stablyai/orca/blob/041baf356b368d773f333e76375ce860fba2481b/src/shared/agent-session-option-catalog-omp.ts)、[启动参数校验](https://github.com/stablyai/orca/blob/041baf356b368d773f333e76375ce860fba2481b/src/main/runtime/rpc/methods/orchestration/worker/worker-launch-preferences.ts)、[通用能力声明](https://github.com/stablyai/orca/blob/041baf356b368d773f333e76375ce860fba2481b/src/shared/orchestration-runtime-capabilities.ts)。

## 原生模型目录暂不自动探测

`omp models --json` 不是已核实的只读接口。命令初始化可能迁移设置或写入数据库、准备原生缓存、加载并关闭扩展；未缓存的 provider 发现还可能执行配置中的命令或刷新 OAuth。`--no-extensions` 不能消除其它副作用，也没有核实到只读或离线模式。因此本轮没有执行该命令，当前工作台不在后台读取原生模型目录。

后续目录接入必须有明确的会话所有权和副作用边界。OMP 的 CLI 目录与 RPC `get_available_models` 过滤范围不同：前者不能当作当前会话的 `enabledModels` 选择结果；后者返回的完整模型对象可能带有不应传给前端的连接字段，需要白名单投影。角色选择器由 OMP 解析，不能把 `@smol` 的当前展开结果永久当作请求模型。

## 身份隔离和输出分页

新观察到的 `ORCA_AGENT_SESSION_SPAWN_TOKEN` 是 Orca 为原生子进程设置的归属令牌，不是 `--from` 调用者身份。ThoughtsFlow 的 CLI 子进程现在清除该变量，防止继承外部 Agent 的进程归属；已有 `ORCA_AGENT_SESSION_ID` 隔离继续保留。测试只注入虚构 token，不读取真实令牌或模型凭据。

worker 输出的 terminal/transcript 来源和不透明游标契约保持兼容。工作台现在根据当前 source 读取相应的 `limited` 标记，并要求返回游标非空且推进，才显示下一页入口。`transcript.limited: false` 不再仅因有游标就错误显示“继续读取”；重复游标也不导致无进展分页。分页结束只说明当前观察的分页状态，不是任务完成或全部输出已获证实。

固定来源：[子进程环境封装](https://github.com/stablyai/orca/blob/041baf356b368d773f333e76375ce860fba2481b/src/main/runtime/structured-session-child-env.ts)、[spawn token 进程归属扫描](https://github.com/stablyai/orca/blob/041baf356b368d773f333e76375ce860fba2481b/src/main/runtime/agent-session-spawn-token-process-scan.ts)、[输出结构](https://github.com/stablyai/orca/blob/041baf356b368d773f333e76375ce860fba2481b/src/shared/orchestration-worker-output.ts)、[转录分页](https://github.com/stablyai/orca/blob/041baf356b368d773f333e76375ce860fba2481b/src/main/runtime/orchestration/worker-transcript-read.ts)、[来源游标](https://github.com/stablyai/orca/blob/041baf356b368d773f333e76375ce860fba2481b/src/main/runtime/orchestration/worker-output-cursor.ts)。
